CSS-LAB-BOA / level 04

sprintf() — Oversized Formatted OutputREQUIRED

Formats values into a buffer with no limit on how long the resulting string is allowed to be.

1. Overview & Vulnerability Theory

The vulnerable function

sprintf(buffer, format, ...) — writes a formatted string into buffer. The length of the result depends entirely on the format string and its arguments — sprintf() has no parameter through which to tell it buffer's actual size.

Why it fails at the memory level

Unlike strcpy()/strcat(), the overflow length here isn't just 'however long the input string is' — it's whatever the fully-expanded format string produces, which can be influenced by multiple arguments, width specifiers, or (in more complex cases than this lab) attacker-controlled format strings. The write mechanism is identical to the others once the content is known: unbounded copy into a fixed buffer.

higher addresses ┌─────────────────────────┐ │ saved return address │ <- overflow eventually reaches here ├─────────────────────────┤ │ saved base pointer │ ├─────────────────────────┤ │ local buffer (16B) │ <- write starts here, grows upward └─────────────────────────┘ lower addresses stack grows DOWN, but an overflowing WRITE goes UP — toward the frame pointer and return address, not away from them.

Classification

CWE-120 / CWE-134 — Buffer Copy without Checking Size of Input; CWE-134 (Use of Externally-Controlled Format String) is the closely related, more severe sibling bug when the format string itself — not just an argument — comes from untrusted input.

3. The Secure Rewrite

vuln.c

#include <stdio.h>

void vulnerable_format(char *input) {
    char buffer[32];
    sprintf(buffer, "User: %s", input);
    /* VULNERABLE: no length limit */
    printf("%s\n", buffer);
}

int main(int argc, char *argv[]) {
    if (argc < 2) return 1;
    vulnerable_format(argv[1]);
    printf("Returned safely.\n");
    return 0;
}

secure.c

#include <stdio.h>

void secure_format(char *input) {
    char buffer[32];
    snprintf(buffer, sizeof(buffer),
              "User: %s", input);
    printf("%s\n", buffer);
}

int main(int argc, char *argv[]) {
    if (argc < 2) return 1;
    secure_format(argv[1]);
    printf("Returned safely.\n");
    return 0;
}

What changed, and why it's actually safe

snprintf() is sprintf()'s bounds-aware sibling: it takes the destination's size as an explicit second argument and will never write past it, truncating the formatted output (and always null-terminating) if the result would otherwise be too long.

Proof: same malformed input, secure build

$ /tmp/secure "$(python3 -c "print('A'*40)")"
User: AAAAAAAAAAAAAAAAAAAAAAAAA
Returned safely.
# Output capped at 31 chars + null terminator. No crash.
