CSS-LAB-BOA / level 01

gets() — Unbounded ReadREQUIRED

The function that cannot be called safely under any circumstances, in any context, with any input — which is why it no longer exists in the C11 standard.

1. Overview & Vulnerability Theory

The vulnerable function

gets(buffer) — reads characters from stdin into buffer until a newline or EOF, with absolutely no length argument. There is no way to tell gets() how big the destination is.

Why it fails at the memory level

Every other unsafe function in this lab at least takes a size somewhere in its call signature that a careless programmer could get wrong. gets() doesn't even offer that chance — the API itself has no parameter for buffer size, so it is structurally incapable of a bounds check. Input of any length is copied byte-for-byte onto the stack starting at buffer's address and marching upward through adjacent memory.

higher addresses ┌─────────────────────────┐ │ saved return address │ <- overflow eventually reaches here ├─────────────────────────┤ │ saved base pointer │ ├─────────────────────────┤ │ local buffer (16B) │ <- write starts here, grows upward └─────────────────────────┘ lower addresses stack grows DOWN, but an overflowing WRITE goes UP — toward the frame pointer and return address, not away from them.

Classification

CWE-120 / CWE-242 — Buffer Copy without Checking Size of Input; CWE-242 specifically flags gets() as an inherently dangerous function that should never be used.

3. The Secure Rewrite

vuln.c

#include <stdio.h>

void vulnerable_read(void) {
    char buffer[16];
    printf("Enter your name: ");
    gets(buffer); /* VULNERABLE: no bounds
                     checking, no length arg */
    printf("Hello, %s!\n", buffer);
}

int main(void) {
    vulnerable_read();
    printf("Returned safely.\n");
    return 0;
}

secure.c

#include <stdio.h>
#include <string.h>

void secure_read(void) {
    char buffer[16];
    printf("Enter your name: ");
    if (fgets(buffer, sizeof(buffer), stdin)) {
        buffer[strcspn(buffer, "\n")] = '\0';
        printf("Hello, %s!\n", buffer);
    }
}

int main(void) {
    secure_read();
    printf("Returned safely.\n");
    return 0;
}

What changed, and why it's actually safe

fgets() takes the destination buffer's size as a mandatory third argument and will never write past it — it's structurally incapable of this overflow, the same way gets() was structurally incapable of avoiding it. The one adjustment needed is that fgets() keeps the trailing newline character (gets() discards it), so strcspn() is used to find and strip it.

Proof: same malformed input, secure build

$ python3 -c "print('A'*40)" | /tmp/secure
Enter your name: Hello, AAAAAAAAAAAAAAA!
Returned safely.
