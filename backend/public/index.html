the idea in one minute

A buffer is a fixed-size chunk of memory. C does not stop you writing past its end — the extra bytes spill into whatever sits next in memory, including, on the stack, the address execution returns to when the function ends. Every level below is the same shape: an unsafe call, an input that proves it, a safe rewrite beside it.

the levels

01gets() — unbounded read

No length argument exists for it to respect — removed from the C standard for exactly this reason.

cd 01-gets && gcc -g -fsanitize=address -fno-stack-protector -o /tmp/v vuln.c echo "Bhushan" | /tmp/v python3 -c "print('A'*40)" | /tmp/v

Fix: fgets(buffer, sizeof(buffer), stdin).

02strcpy() — unchecked copy

Copies until a null byte, blind to the destination's size.

cd 02-strcpy && gcc -g -fsanitize=address -fno-stack-protector -o /tmp/v vuln.c /tmp/v "Bhushan" /tmp/v "$(python3 -c "print('A'*40)")"

Fix: strncpy(dest, src, sizeof(dest)-1).

03strcat() — unchecked concatenation

Appends with no sense of remaining capacity.

cd 03-strcat && gcc -g -fsanitize=address -fno-stack-protector -o /tmp/v vuln.c /tmp/v "$(python3 -c "print('A'*40)")"

Fix: strncat(dest, src, remaining).

04sprintf() — oversized output

No limit on the formatted result's length.

cd 04-sprintf && gcc -g -fsanitize=address -fno-stack-protector -o /tmp/v vuln.c /tmp/v "$(python3 -c "print('A'*40)")"

Fix: snprintf(buf, sizeof(buf), …).

05memcpy() — incorrect byte count

Copies exactly as told — correctly. The bug is trusting an unvalidated length.

cd 05-memcpy && gcc -g -fsanitize=address -fno-stack-protector -o /tmp/v vuln.c /tmp/v "$(python3 -c "print('A'*40)")"

Win condition: craft an input that flips the adjacent access_granted variable. Fix: clamp the length to sizeof(buffer)-1.

06array indexing — invalid index

No bound on the index itself, positive or negative.

cd 06-array-indexing && gcc -g -fsanitize=address -o /tmp/v vuln.c /tmp/v 15 1 # out of bounds /tmp/v -5 1 # negative index

Fix: validate 0 ≤ idx < 10 before every access.

07return-address overwrite bonus

The deepest level: overwrite the saved return address to redirect execution into a function never called by the program. Canaries, PIE and ASLR are deliberately off here — the one place in this lab those protections are disabled. See docs/solution.md for the full gdb walkthrough.

faq

Is this actually safe to run?

Yes — each session is a disposable, network-isolated Docker container with a read-only filesystem outside a small scratch area and hard resource limits. Never run these binaries outside the sandbox.

What is AddressSanitizer?

A compiler instrumentation that surrounds allocations with poisoned "redzones," catching out-of-bounds access the instant it happens, with the exact address and stack trace.

I got "Read-only file system" compiling.

Compile into /tmp, the writable scratch area, not the level directory itself.

What's different between vuln.c and secure.c?

Only the one function under study, swapped for its bounds-aware counterpart. Same input, different outcome.
